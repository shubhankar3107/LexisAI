ADR 17 — Centralized Domain Enums

Decision

Store domain enums in a dedicated app/enums package.

Rationale

* Separation of concerns
* Better discoverability
* Reusable across models, services, and APIs
* Scales cleanly as the domain grows

Alternatives Considered

* Defining enums inside model files
* A single enums.py file

Why Rejected

* Model files become cluttered.
* A single enums.py eventually becomes a large miscellaneous file.
* Poor organization as the number of enums increases.
