ADR 21 — Single Configuration Source

Status

Accepted

⸻

Context

Both the application and Alembic need a database connection.

A common beginner setup is:

.env
│
└── DATABASE_URL=...

and also

alembic.ini

sqlalchemy.url=postgresql://...

Now the same configuration exists in two places.

This creates duplication.

Imagine changing your PostgreSQL password.

You would have to update:

.env

and

alembic.ini

If you forget one, the application and Alembic connect to different databases.

Decision

LexisAI will have one source of truth for configuration.

The database URL lives only in:

.env
        │
        ▼
config.py
        │
        ▼
settings.database_url

Alembic reads the URL from the application’s configuration rather than maintaining its own copy.

⸻

Why We Chose This

Single Source of Truth

There is only one place to update.

⸻

No Configuration Drift

The application and Alembic always use the same database.

⸻

Easier Environment Management

Switching between:

* Development
* Testing
* Staging
* Production

requires changing only the application’s configuration.

⸻

Better Scalability

Later we’ll have many settings:

DATABASE_URL

REDIS_URL

OPENAI_API_KEY

UPLOAD_DIRECTORY

MAX_FILE_SIZE

JWT_SECRET

Keeping all configuration in one system is much cleaner than scattering values across multiple files.

Alternatives Considered

Option A — Default Alembic (Rejected)

alembic.ini

sqlalchemy.url=...

Pros

* Works out of the box.
* Matches Alembic tutorials.

Cons

* Duplicate configuration.
* Easy for values to get out of sync.
* Harder to manage multiple environments.

⸻

Option B — Single Source via config.py (Accepted)

.env
        │
        ▼
config.py
        │
        ▼
settings.database_url
        │
        ▼
Alembic

Pros

* One source of truth.
* No duplicated credentials.
* Consistent across the application.
* Easier deployment.

⸻

Consequences

Positive

* Cleaner architecture.
* Easier maintenance.
* Fewer configuration bugs.
* Better long-term scalability.

Trade-offs

We encountered one subtle issue:

configparser

↓

%40

↓

Interpolation Error

Because Alembic internally uses Python’s configparser, URL-encoded characters such as %40 required us to escape % before calling:

config.set_main_option(
    "sqlalchemy.url",
    settings.database_url.replace("%", "%%"),
)

This was a small integration detail, not a flaw in the architectural decision itself.

Final Architecture

                .env
                  │
                  ▼
          app/core/config.py
                  │
                  ▼
             settings
                  │
      ┌───────────┴───────────┐
      │                       │
      ▼                       ▼
 Application             Alembic
      │                       │
      └───────────┬───────────┘
                  ▼
             PostgreSQL
