ADR 12 — Request-Scoped Database Sessions

Decision

Every HTTP request will receive its own SQLAlchemy Session.

Rationale

* Transaction isolation
* No shared mutable state
* Safe concurrent requests
* Automatic cleanup
* Matches FastAPI best practices

Alternatives Considered

* Global Session
* Long-lived Sessions
* Manual connection management

Why Rejected

* Unsafe for concurrent users
* Difficult transaction management
* Increased risk of stale state and resource leaks
