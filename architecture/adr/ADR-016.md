ADR 16 — Database-Owned Timestamps

Decision

The database will generate timestamps using server-side defaults rather than Python.

⸻

Rationale

* The database is the source of truth.
* Every application instance gets consistent timestamps.
* Works correctly with multiple servers.
* Independent of application server clock drift.
* Simplifies model creation.

⸻

Alternatives Considered

Python-generated timestamps

Why Rejected

* Depends on application server time.
* Different application instances could have slightly different clocks.
* Easy to accidentally generate naive datetimes.
* Business logic becomes responsible for infrastructure concerns.
